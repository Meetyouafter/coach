# Личный журнал тренировок

**React + Vite → Vercel Functions → PostgreSQL в Neon.** Несколько пользователей, регистрация и вход по логину и паролю. Каждый пользователь видит только свой журнал.

Все тренировки хранятся в PostgreSQL. Дополнительного пароля к базе в интерфейсе и выбора места хранения нет. Журнал не записывается в LocalStorage или IndexedDB. В браузере сохраняются только предпочтение темы и сигнал смены аккаунта между вкладками; авторизация использует HttpOnly-cookie.

## Как работает

1. На стартовом экране выбери «Регистрация», придумай логин и пароль. Логин — 3–40 букв, цифр или символов `_ . -`; регистр логина не важен. При регистрации пароль должен содержать от 12 до 1024 символов. При регистрации его нужно ввести дважды; при входе — один раз.
2. После регистрации сразу открывается личный журнал. При следующих посещениях используй вкладку «Войти».
3. Подходы, бег и статусы автоматически сохраняются в базе. «Сохранено в базе» означает подтверждённую запись сервером.

Если сеть недоступна, изменения остаются только в памяти открытой страницы, показывается ошибка сохранения и выполняется повторная отправка. Не закрывай страницу до сохранения или экспортируй изменения в JSON. При первой загрузке без связи нельзя редактировать пустую подмену облачного журнала. Выход из аккаунта сначала дожидается сохранения.

Разные логины могут иметь одинаковые пароли — это независимые аккаунты. Пароли хранятся как scrypt-хеши с индивидуальной случайной солью. Восстановление и смена пароля пока не реализованы.

## Локальный запуск

Требуются Node.js 24 и PostgreSQL в Neon.

```sh
npm ci
cp .env.example .env.local
```

Впиши в `.env.local`:

- `DATABASE_URL` — полную строку подключения из Neon → Connect.
- `AUTH_SECRET` — постоянный секрет сервера, минимум 16 символов. Это не пароль пользователя. Сгенерировать: `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`.

Если рабочий `.env` уже настроен, не заменяй его. Для совместимости существующий `APP_PASSWORD` используется вместо `AUTH_SECRET`, если последнего нет. Все пользователи создают собственные пароли на странице регистрации.

```sh
npm run db:migrate
npm run dev
```

Открой выведенный Vite адрес, обычно `http://127.0.0.1:5173`. Локальное приложение использует указанную базу Neon; для разработки лучше отдельная ветка базы. При изменении серверного кода или переменных перезапусти dev-сервер. `.env` и `.env.local` игнорируются Git.

## Развёртывание на Vercel

Для личного некоммерческого проекта подходят [Vercel Hobby](https://vercel.com/docs/plans/hobby) и [Neon Free](https://neon.com/pricing), в пределах лимитов тарифов.

1. Создай проект **Neon Free**, нажми **Connect**, скопируй строку подключения PostgreSQL с параметрами SSL.
2. Импортируй Git-репозиторий в Vercel. Framework — **Vite**, Node.js — **24.x**, корень — этот каталог. Остальные параметры заданы в `vercel.json`.
3. Добавь в Environment Variables `DATABASE_URL` и `AUTH_SECRET`. Не используй префикс `VITE_` для этих секретов.
4. Нажми Deploy. `npm run vercel-build` проверит настройки, применит SQL-миграции и соберёт приложение. Существующие записи сохраняются.
5. Открой сайт, зарегистрируй аккаунт, сохрани подход и перезагрузи страницу для проверки.

Для Preview используй отдельную ветку базы, чтобы тестовые развёртывания не меняли основной журнал. После изменения переменных Vercel нужен Redeploy. Изменение `AUTH_SECRET` завершает старые сессии, но не удаляет аккаунты с логинами: пользователи смогут войти заново.

## Команды и устройство

```sh
npm run build         # React → dist, без обращения к базе
npm run db:migrate    # применить схему PostgreSQL
npm run vercel-build  # проверка env, миграции и сборка
npm test              # PostgreSQL, аккаунты, изоляция, синхронизация, темы
```

- `src/AuthGate.jsx` — регистрация и вход.
- `src/App.jsx`, `src/components/Workout.jsx` — программа, тренировка и история.
- `src/store.js` — загрузка и сохранение в API; без локальной копии.
- `shared/` — программа и проверка формата записей.
- `api/session.js` — аккаунты и подписанные сессии на 30 дней.
- `api/journal.js` — журнал пользователя из проверенной сессии.
- `server/users.js`, `server/auth.js` — учётные записи, пароли, cookie.
- `server/database.js` — параметризованные PostgreSQL-запросы через Neon HTTP driver.
- `db/` — схема журналов, пользователей и логинов.

Изменение журнала и проверка его ревизии выполняются одним SQL-запросом: конфликт устройств возвращает `409`. API проверяет Origin и сверяет ожидаемый аккаунт с подписанной сессией. Клиентский `userId` не даёт доступ к чужому журналу.

Тесты используют локальный PostgreSQL-движок PGlite, без аккаунта Neon и сетевых запросов. Переключатель темы — [Radix UI Switch](https://www.radix-ui.com/primitives/docs/components/switch) (MIT), иконки — [Lucide](https://lucide.dev/) (ISC/MIT); уведомления находятся в `public/third-party-notices.txt`.

## Обновление старой версии

Выполни `npm run db:migrate`, затем перезапусти приложение. Нужно войти заново. Если раньше был вход только по паролю, зарегистрируй логин с тем же паролем — существующий аккаунт получит логин и сохранит записи. До завершения этого перехода сохрани прежний серверный секрет. Записи первоначального общего журнала `owner` доступны при регистрации со старым паролем владельца из `APP_PASSWORD`.

Старые кеши журналов автоматически удаляются из браузера при открытии новой версии. Темы оформления продолжают запоминаться.
