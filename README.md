# Личный журнал тренировок

Личный журнал тренировок: **React + Vite → Vercel Functions → PostgreSQL в Neon**. Cloudflare, D1 и OpenAI Sites больше не нужны. Приложение рассчитано на одного владельца: один пароль открывает один журнал на всех устройствах.

Сохранены программа на 12 недель, подходы и бег, таймер, история, импорт/экспорт JSON и локальная копия при сбоях связи. PostgreSQL хранит журнал и ревизию; устаревшая копия не перезаписывает изменения другого устройства.

## Развёртывание бесплатно на Vercel

Для личного некоммерческого использования подходят [Vercel Hobby](https://vercel.com/docs/plans/hobby) и [Neon Free](https://neon.com/pricing), пока использование укладывается в их лимиты. Выбирай именно бесплатные планы. Отдельный постоянно работающий сервер, платная авторизация и cron не нужны.

1. Создай проект на [Neon](https://console.neon.tech/) с планом **Free**. В **Connect** скопируй PostgreSQL connection string; можно использовать **Pooled connection**. Сохрани параметры SSL в строке.
2. Загрузи репозиторий в GitHub и импортируй его в Vercel через **Add New → Project**. Корень проекта — этот каталог; preset **Vite**, Node.js **24.x**. `vercel.json` уже задаёт сборку и `dist`.
3. До первого Deploy добавь в **Environment Variables**:

   | Имя | Значение |
   | --- | --- |
   | `DATABASE_URL` | Полная строка подключения из Neon |
   | `APP_PASSWORD` | Уникальный случайный пароль, 16–1024 символа |

   Добавь переменные в **Production**. Для Preview используй отдельную ветку/базу Neon и свои переменные, чтобы тестовые развёртывания не меняли основной журнал. Пароль можно сгенерировать командой `node -e "console.log(require('node:crypto').randomBytes(24).toString('base64url'))"`.
4. Нажми **Deploy**. Vercel выполнит `npm run vercel-build`: проверит настройки, создаст таблицу в PostgreSQL, соберёт React и развернёт две API-функции. Существующие записи при повторной сборке сохраняются.
5. Открой полученный адрес и введи `APP_PASSWORD`. Начни тренировку, сохрани подход и перезагрузи страницу: запись должна остаться, а статус — стать «Синхронизировано».

Если проект уже импортирован, после добавления/изменения переменных сделай **Redeploy**. Если подключаешь Neon через Vercel Marketplace, проверь, что интеграция создала именно `DATABASE_URL`; при другом имени добавь эту переменную вручную.

`DATABASE_URL` и `APP_PASSWORD` используются только на сервере. Не добавляй префикс `VITE_`: такие переменные попадут в браузерную сборку. Смена `APP_PASSWORD` завершает действие ранее выданных сессий. Ненужные Preview-развёртывания можно не включать.

## Локальный запуск

Нужны Node.js 24 и база Neon (лучше отдельная dev-ветка).

```sh
npm ci
cp .env.example .env.local
```

Впиши свои `DATABASE_URL` и `APP_PASSWORD` в `.env.local`, затем:

```sh
npm run db:migrate
npm run dev
```

Открой адрес Vite, обычно `http://127.0.0.1:5173`. Vite запускает React и те же API-обработчики, что используются на Vercel. Изменения интерфейса подхватываются автоматически; после изменения серверных файлов или переменных перезапусти dev-сервер. `.env.local` не попадает в Git. Настоящая база используется и локально, поэтому не подставляй основную production-строку для экспериментов.

```sh
npm run build         # статическая сборка React без доступа к базе
npm run db:migrate    # создание таблицы в указанной PostgreSQL
npm run vercel-build  # проверка env, создание таблицы и сборка для Vercel
npm test              # PostgreSQL/API, вход, конфликты, офлайн-синхронизация
```

Тесты выполняют настоящий PostgreSQL SQL в локальном PGlite; учётная запись Neon и сетевой доступ для них не нужны. Полное развёртывание требует настроенных аккаунтов Vercel и Neon.

## Устройство приложения

- `src/App.jsx`, `src/components/Workout.jsx` — React-интерфейс.
- `src/AuthGate.jsx` — вход и выход.
- `src/store.js` — локальная копия и синхронизация.
- `shared/` — программа и общая проверка журнала.
- `api/session.js` — вход по паролю и подписанная HttpOnly-cookie на 30 дней.
- `api/journal.js` — чтение и сохранение журнала владельца.
- `server/database.js` — параметризованные PostgreSQL-запросы через Neon HTTP driver.
- `db/0001_journal.sql` — схема PostgreSQL; повторное применение не удаляет записи.
- `vercel.json` — параметры развёртывания.

Переключатель темы использует [Radix UI Switch](https://www.radix-ui.com/primitives/docs/components/switch) (MIT). Иконки солнца, луны и гантели, включая favicon, — [Lucide](https://lucide.dev/) (ISC/MIT). Лицензионные уведомления доступны в `public/third-party-notices.txt` и включаются в сборку.

Таблица `workout_journals` содержит `user_id`, `revision` и `journal` типа JSONB. Изменение и проверка ревизии выполняются одним SQL-запросом; конфликт возвращает `409`. Запись и вход проверяют Origin. Авторизация не зависит от заголовков OpenAI или клиентского идентификатора.

Локальная копия остаётся в браузере после выхода, чтобы не потерять несинхронизированные записи. При конфликте экспортируй её через «История → Экспорт JSON», прежде чем очищать данные браузера. После истечения сессии нужно снова войти; уже открытое приложение сохраняет изменения локально при сбое сети, но для входа после перезагрузки нужна связь с сервером.
