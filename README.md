# Зал и бег

Мобильный журнал 12-недельной программы на **React + Cloudflare Worker + D1 (SQLite)**. React отвечает за интерфейс, Worker — за API и проверку записей, D1 — за пользовательские журналы. LocalStorage хранит резервную копию и изменения, ожидающие синхронизации.

Сохранены программа тренировок, запись подходов и бега, таймер отдыха, история упражнений, старый формат журнала и импорт/экспорт JSON. Синхронизация использует номер ревизии: устаревшая копия не перезаписывает изменения другого устройства. При конфликте нужно экспортировать местную копию, прежде чем очищать данные браузера или загружать другую версию журнала.

## Локальный запуск

Требуется Node.js 24 и npm.

```sh
npm ci
npm run dev
```

Открой адрес, который выведет Wrangler, обычно `http://127.0.0.1:8787`. Команда собирает React, применяет SQL-миграции и запускает Worker с локальной D1. Данные сохраняются в `.wrangler/state/` между перезапусками. После изменения исходников перезапусти `npm run dev` для пересборки.

`wrangler.local.jsonc` предназначен только для разработки. На loopback-адресах он использует пользователя `local-developer` без входа. Эта настройка не включается в `.openai/hosting.json` и не должна переноситься в production.

## Команды

```sh
npm run build       # React и Worker → dist/server/index.js
npm run db:migrate  # миграции только локальной D1
npm test            # SQL/API, конфликты, офлайн-синхронизация, программа и старые записи
```

## Структура

- `src/App.jsx` — React-приложение, план и история.
- `src/components/Workout.jsx` — тренировка, формы, техника и таймер.
- `src/store.js` — состояние журнала, локальная копия, повторная синхронизация.
- `src/journal.js` — история подходов и расчёты.
- `shared/program.js` — программа тренировок.
- `shared/validate.js` — общая проверка данных клиента и сервера.
- `worker/server.js` — API и раздача React-приложения.
- `drizzle/0000_journal.sql` — схема D1.

## База и API

Таблица `workout_journals` хранит `user_id`, `revision` и JSON `journal`. Схема и формат записей совместимы с прежней версией; переносить или пересоздавать существующую базу не нужно.

- `GET /api/journal` возвращает `{ revision, journal }` текущего пользователя.
- `PUT /api/journal` принимает `{ revision, journal }` и возвращает новую ревизию. Конфликт возвращает `409`; данные проверяются до записи.

SQL-запросы параметризованы. Production использует проверенный заголовок `oai-authenticated-user-id` от доверенного шлюза; клиентский заголовок шлюз должен удалить и заменить своим. PUT также проверяет Origin.

## Развёртывание

`npm run build` создаёт ES-модуль Cloudflare Worker в `dist/server/index.js` и копирует `.openai/hosting.json`. Для production нужна привязка D1 с именем `DB`, применённая схема из `drizzle/` и доверенный слой авторизации OpenAI Sites либо эквивалентный шлюз.

В текущем `.openai/hosting.json` указан только D1 binding; идентификатор Site ещё не задан. Для публикации через Sites нужно добавить `project_id` существующего проекта. Локальная база и облачная база независимы. Пользовательских записей из облака в репозитории нет; перенос между окружениями выполняется через экспорт и импорт в разделе «История».
